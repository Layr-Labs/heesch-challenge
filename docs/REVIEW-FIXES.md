## Finding 1 — [P0] Plane tilers can win the benchmark

**Problem.** The gate only rejected shapes it could *prove* tile; boundary
criteria existed for squares only and the known-tiler table held square
entries only, so every hex/iamond tiler fell through to `INCONCLUSIVE`,
which is scored. Demonstrated exploit: a monohex with two coronas scored
2.0, beating the 1.0 baseline.

**Fix (two independent layers).**

1. *Exhaustive known-tiler tables* — `heesch_verify/known_tilers.json`
   regenerated by `tools/gen_tiler_table.py`: every polyomino ≤ 8 cells
   (503 digests), polyhex ≤ 6 (111), polyiamond ≤ 9 (251 then; 250 after the V-heptiamond correction in 9f76ad6; table since replaced by the census — see addendum). Entries are
   derived by census arithmetic against Kaplan 2022's published per-size
   non-tiler counts (arXiv:2105.09438 Tables 1/3/5) — counts our own sweeps
   independently reproduced — and the generator hard-asserts every count
   before writing, so an unsound table cannot be produced.
2. *Hex boundary-word criteria* — `heesch_verify/boundary.py` gained
   `hex_boundary_word()` (CCW outer-boundary walk over the 6-letter edge
   alphabet) and the Beauquier–Nivat / Conway criteria were parametrized
   over the alphabet (`n_dirs`; opposite = +3 mod 6). These constructively
   prove hex tilings of **any** size; 33 of the 34 polyhexes ≤ 5 cells are
   proven by the criteria alone.

**Soundness note.** The gate's verdict rule is unchanged: `TILER` only on
constructive proof (table membership from published exhaustive data, or an
explicit factorization); never `NON_TILER`. Cross-checked: zero false
`TILER` verdicts across all 47+ known non-tilers in the calibration corpus.

**Residual, as documented at the time (superseded — see addendum).**
Iamond boundary words were not implemented (table covered ≤ 9); tilers
outside both layers could hold a *true-but-hollow* lower-bound entry
(`Hc ≥ k` is mathematically true even for tilers) until identified.

**Addendum 2026-08-17.** The 2026-08-11 vulnerability review already showed
the residual was "trivially exploitable, not exotic" (a 132-cell comb scored
5.0; iamond words were then implemented, finding V2). The 2026-08-16
comparative audit went further: at the first size beyond these tables the
constructive criteria missed 89 nine-omino, 37 seven-hex and 79 ten-iamond
tilers, and a 9-omino tiler scored through the harness. Resolution: the
known-tiler table (503/111/250 digests) is replaced by Kaplan's complete
non-tiler census (exact for O ≤ 10, H ≤ 8, I ≤ 12), and the harness is
fail-closed — an unproven shape is `GATE_INCONCLUSIVE`, never scored. See
`docs/audits/2026-08-16-comparative-audit-response.md`.

**Tests.** `tests/test_harness.py::test_p0_monohex_tiler_rejected` (the
reviewer's exact exploit, now permanently red-barred);
`tests/test_calibration.py` gate guard over all corpus non-tilers.

## Finding 2 — [P2] Failed runs retain a stale trusted score

**Problem.** `score.json` was never deleted before verification while the
workflow uploads it under `if: always()`; a failed run could expose an
older result (mainly on retries / self-hosted runners).

**Fix.** `benchmark.sh` deletes `score.json` before *any* fallible work
(the flock pattern, comment included), and `harness/verify.py::main()`
unlinks its target at start. The sandbox design adds a second guarantee:
the harness writes the score into a scratch directory
(`HEESCH_SCORE_DIR`) and `benchmark.sh` copies it to the repo root only
after full success — nonzero exit therefore structurally cannot leave a
score behind.

**Tests.** `tests/test_harness.py::test_stale_score_removed_on_failure`.

## Finding 3 — [P2] Valid LRAT proofs reported as invalid

**Problem.** `heesch_encoder/proofcheck/checkers.py` accepted only the
substring `s VERIFIED`, but the vendored `lrat-check` emits `c VERIFIED`
(lrat-check.c:490). Every valid LRAT proof would have failed when the
record tier goes live.

**Fix.** Per-checker, **line-anchored** verdict matching: drat-trim
`s VERIFIED`; lrat-check `c VERIFIED`; cake_lpr lines starting
`s VERIFIED`; any `NOT VERIFIED` line overrides. Line anchoring matters in
the *other* direction too — drat-trim prints a non-verdict
`c VERIFIED derivation: ...` progress line (drat-trim.c:858) that substring
matching on the "fix" would have wrongly accepted. Both traps are covered.

**Tests.** `tests/encoder/test_checker_verdicts.py` (11-case matrix);
`tests/encoder/test_ml_proof_pipeline.py` runs the real checkers in CI.

## Finding 4 — [P2] The trusted workflow is non-hermetic

**Problem.** `benchmark.yml` used `ubuntu-latest`, mutable action tags,
default persisted credentials, no fixed Python; `pyproject.toml` allowed
any future setuptools.

**Fix.** Rebuilt on the flock/ecdsafail template:

- `runs-on: ubuntu-24.04`; SHA-pinned actions
  (`checkout@93cb6efe… # v5.0.1`, `upload-artifact@b7c566a7… # v6.0.0`,
  `setup-python@5fda3b95… # v7.0.0` with Python 3.12);
- `persist-credentials: false`, `clean: true`, `fetch-depth: 2`;
- independent **submission-surface check** (single-parent commit; diff must
  stay inside `submission/`) — defense in depth over Yukon's own
  enforcement;
- runner-preflight recorded to a diagnostics artifact; score artifact with
  `if-no-files-found: error`, `retention-days: 30`;
- strict score extraction: `jq -er '.score | select(type == "number")'`;
- `build-system requires = ["setuptools==84.0.0"]` (exact pin).

## Restructure (reviewer TODOs) — layout, portability, sandboxing

Matching the reference challenges exactly:

- **Top-level `setup.sh` / `benchmark.sh`** (renamed from `.yukon/run.sh`),
  invoked verbatim by `benchmark.json`
  (`["bash","-lc","./setup.sh"]` / `./benchmark.sh`); `scorePath` moved to
  root `score.json`.
- **Generalized Python setup** — `$PYTHON` override, then
  `python3.13 → 3.12 → 3.11 → python3 → python` discovery with a ≥ 3.11
  version gate and actionable errors; venv at `./.venv-bench`, re-derived
  by absolute path in `benchmark.sh` (env does not persist between Yukon's
  setup and benchmark commands); setup is the only networked step.
- **Sandboxed scoring** — the verify stage runs under bubblewrap (Linux:
  read-only filesystem, no network namespace, all capabilities dropped,
  scratch-only writes) or Seatbelt (macOS), with an unconfined dev
  fallback that warns. Our harness executes **no competitor code** (the
  submission is a data file), so this is defense-in-depth against
  parser-exploit classes in our own code. Two CI-discovered environment
  fixes are in the follow-up commits: privileged netns setup via
  `sudo -n bwrap` (GitHub runners deny unprivileged `RTM_NEWADDR`), and
  binding the repo at a scratch-anchored path (with `--cap-drop ALL`, even
  root loses `CAP_DAC_OVERRIDE` and cannot traverse the runner's 0750
  `$HOME`).

**Verification.** Full suite: 337 tests green, including the e2e that runs
`setup.sh && benchmark.sh` with the sandbox engaged on ubuntu-24.04 and
validates the score with strict `jq`. Encoder golden digests are
byte-identical across the entire remediation (no scoring semantics
changed).
